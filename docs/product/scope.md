# 产品范围（MVP）

## 产品目标

提供一个社区服务入口，让居民了解社区服务和公告、浏览商城商品并提交订单；运营人员可通过后台维护展示内容和管理订单。首期重点是内容展示和人工履约，不依赖饮水机设备或在线支付。

## 小程序用户端

### 包含

- 社区首页：社区名称、介绍、公告及服务入口。
- 社区服务展示：服务名称、介绍、图片、联系方式或服务说明。
- 商城首页及商品分类。
- 商品列表、商品详情、价格、图片和上下架状态。
- 提交订单：选择商品和数量，填写联系人、电话、收货地址及备注。
- 我的订单：查看本人订单及订单状态。
- 支付状态展示：新订单默认为“未支付”；不发起微信支付。

### 暂不包含

- 饮水机、售水机、净水设备联网和远程控制。
- 微信支付、退款、支付回调和自动分账。
- 促销券、积分、会员等级、团购和分销。
- 自动配送调度、骑手端和物流轨迹。
- 多社区、多商户隔离和复杂角色权限。

## 运营后台

### 包含

- 管理员登录。
- 社区公告及服务展示内容维护。
- 商品分类和商品新增、编辑、上下架。
- 商品图片上传至 ECS 本地持久目录。
- 订单列表、详情、按订单号/联系人/状态筛选。
- 后台手动创建订单。
- 更新订单履约状态和记录线下收款状态。
- 区分订单来源：小程序提交、后台录入。

### 暂不包含

- 库存预警和复杂库存流水。
- 供应商、采购、财务结算和多级分润。
- 多角色审批流和细粒度数据权限。

## 订单规则建议

- 小程序提交订单后立即保存为真实订单，订单状态为“待确认”，支付状态为“未支付”。
- 后台手动录入的订单进入同一订单列表，来源标记为“后台录入”。
- 运营人员可把线下收款记录标记为“已收款”；这不调用微信支付。
- 订单至少记录下单时的商品名称、单价和数量快照，避免商品改价影响历史订单。
- 用户只能查看归属自己的小程序订单；后台管理员可查看全部订单。

## 首期验收口径

- 运营人员可以在后台新增商品，商品可在小程序端展示。
- 用户可以浏览商品并提交无在线支付订单。
- 用户可以查看自己的订单及状态。
- 运营人员可以检索小程序订单、手动创建订单并更新订单状态。
- 应用容器重建后，数据库和已上传图片仍然存在。
