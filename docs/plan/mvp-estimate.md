# MVP 计划与估时

## 范围基线

- 项目从空仓库开始。
- 一个微信小程序、一个运营后台、一个社区运营主体。
- 包含内容展示、商品管理、无支付真实订单、后台手动录单。
- 不含设备接入、微信支付、库存、优惠券、配送员端和多商户分账。
- 图片存 ECS 本地持久目录，使用 Docker 部署到阿里云 ECS。

## 开发阶段（单名熟悉技术栈的全栈开发者）

| 阶段 | 工作内容 | 估算 |
|---|---|---:|
| 1. 需求和页面定稿 | 页面结构、订单规则、字段与流程确认 | 1–2 个工作日 |
| 2. 项目骨架 | uni-app、Laravel、Filament、MySQL 初始化和开发配置 | 2–3 个工作日 |
| 3. 小程序展示 | 首页、公告/服务、商品列表与详情、个人订单页 | 4–6 个工作日 |
| 4. 后台内容和商品 | 登录、公告/服务/分类/商品维护、图片上传 | 4–6 个工作日 |
| 5. 订单能力 | 小程序提交订单、订单查询、后台列表/详情/手动录单/状态更新 | 5–8 个工作日 |
| 6. 部署与发布准备 | Docker Compose、Nginx、ECS 配置、备份和联调 | 2–4 个工作日 |

**合计：约 18–29 个工作日。** 日历时间约 4–7 周，取决于反馈速度、素材准备、登录规则和部署环境准备情况。实际估时需在页面和订单规则确认后复核。

## 交付顺序

1. 先完成页面原型和字段清单，确认订单状态、配送/自提、登录方式。
2. 先完成后台商品和内容管理，再接小程序展示。
3. 完成小程序下单与后台订单处理。
4. Docker 部署到 ECS，验证数据和图片持久化、备份恢复与访问域名。

## 影响工期的待定项

- 允许游客下单还是强制微信登录。
- 是否做购物车；首期可以直接从商品详情“立即下单”。
- 是否支持多商品合并成单。
- 是否需要地址簿、库存扣减和自提点管理。
- 是否采用阿里云 RDS；首期同机 MySQL 更省成本，但备份责任更多。
- 小程序主体、备案域名、证书和微信审核的准备时间不计入开发工作日。
