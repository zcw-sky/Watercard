# 技术架构

## 推荐技术栈

| 层 | 选择 | 说明 |
|---|---|---|
| 小程序 | uni-app、Vue 3、TypeScript | 首期编译为微信小程序；后续可评估 H5 或其他平台 |
| 管理后台 | Laravel Filament | 复用 Laravel 数据模型，快速实现商品、公告和订单管理 |
| 后端/API | Laravel 13、PHP 8.3+ | 提供小程序 API、后台业务逻辑和图片访问 |
| 数据库 | MySQL | 存放用户、内容、商品、订单和订单明细 |
| 图片存储 | ECS 本地持久目录 | 首期节省对象存储费用，通过配置保留未来迁移空间 |
| 容器编排 | Docker Compose | 单台 ECS 运行 Web/API、Nginx 和 MySQL |

框架选择参考官方能力说明：uni-app Vue 3 可以编译为小程序代码；Laravel 提供 API 资源和认证能力；Filament 用于构建 Laravel 管理面板。

## 逻辑结构

```text
微信小程序（uni-app） ── HTTPS/JSON API ──┐
                                          ├─ Laravel 应用（API + Filament）
运营管理浏览器 ───────── HTTPS ────────────┘              │
                                                         ├─ MySQL
                                                         └─ ECS 本地持久图片目录
```

## 业务模块

- 内容模块：社区简介、公告、服务展示。
- 商城模块：分类、商品、商品图片、上下架。
- 订单模块：订单、订单明细、订单状态和支付状态。
- 用户模块：小程序身份、管理员账号和访问控制。
- 媒体模块：上传校验、图片存储和公开访问 URL。

## 身份与访问控制

- 管理后台使用管理员登录，并通过角色/权限检查限制管理操作。
- 小程序下单和“我的订单”需要能稳定识别用户。建议使用微信登录换取 OpenID，并在服务端建立用户记录。
- 小程序 API 不信任客户端提交的订单价格；服务端根据当前商品价格计算金额。
- 用户订单接口必须按当前登录用户过滤，不能只靠客户端传入用户 ID。

## 图片存储约定

- 图片目录通过环境配置指定，并挂载在 ECS 主机的持久路径中。
- 图片文件名使用不可预测的唯一名称，不直接使用用户上传的原文件名作为路径。
- 限制允许的 MIME 类型和文件大小。
- 数据库保存图片相对路径或存储 key，由后端生成访问 URL。
- 存储驱动保持可配置，未来可切换到阿里云 OSS。

## 第一版不引入

- Redis、消息队列、微服务和 Kubernetes。
- 饮水机设备接入、IoT 设备协议和实时状态服务。
- 微信支付、退款、支付回调和分账。
